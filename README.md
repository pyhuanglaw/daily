# Daily Routine

個人生活循環清單。取代 iPhone 備忘錄的勾選清單：**只有按下「開始新的一天」才會清空勾選**，任務清單本身永久保存。不會在午夜自動重置，也不會依時間自行判斷。

網站網址（GitHub Pages 啟用後）：<https://pyhuanglaw.github.io/daily/>

## 功能

- **起床／唸書／睡前** 三個階段，預設清單只在第一次使用時建立一次。
- 點一下就勾選，立即保存；**自動記錄每一項的完成時間**，顯示在項目右側（跨日的會顯示日期）。
- 不顯示百分比或進度條。
- 第二、三、四顆可各自選擇科目（再點一次取消），科目選項可自行新增、刪除。
- 每個階段：底部「新增項目」直接輸入；「編輯」可改名、刪除（有確認）、拖曳排序（右側 ≡）、「⋯」上移／下移／移到其他階段／科目選項。
- 階段可收合；收合不影響勾選。
- 「開始新的一天」：確認後把本輪封存到紀錄、清空勾選與科目選擇，任務清單完全不變。防連點、單一交易完成。
- 「紀錄」頁：最上方直接展開**本輪紀錄**（依時間或依階段），下方是過去每一輪（唯讀快照，保留當時的名稱、順序、科目與完成時間）。
- 「設定」頁：匯出／匯入 JSON 備份、加入主畫面說明、儲存狀態。底部分頁列隨時可回主畫面。
- PWA：可加入 iPhone 主畫面、離線可用。
- 配色固定為淺黃底、淡紫內容。

## 在 iPhone 加入主畫面

1. 用 **Safari** 開啟 <https://pyhuanglaw.github.io/daily/>。
2. 點下方的「分享」按鈕（方框加向上箭頭）。
3. 往下滑，選「加入主畫面」，再點「新增」。
4. 之後從主畫面的 **Daily** 圖示開啟。

> **注意**：Safari 分頁與主畫面 App 的資料**可能不共用**。請固定只用主畫面 App。若已在 Safari 使用過，先在 Safari 版「設定 → 匯出備份」，再到主畫面 App「匯入備份」。

## 備份（重要）

資料只存在這支裝置的瀏覽器（IndexedDB）。**GitHub Pages 只提供網頁，不會同步或備份你的資料。** 清除 Safari 網站資料、手機故障或換手機都可能遺失資料。

- **匯出**：設定 → 匯出備份 → 在分享選單選「儲存到檔案」（建議存到 iCloud Drive）。
- **匯入**：設定 → 匯入備份 → 選擇備份檔 → 確認覆蓋。格式或版本不正確的檔案會被拒絕，原資料不受影響。
- 建議每週匯出一次。

## 資料設計

IndexedDB 資料庫 `daily-routine`：

| Store | 內容 |
| --- | --- |
| `tasks` | **永久任務模板**：id、階段、名稱、順序、科目選項 |
| `currentCycle` | **當前生活循環**：循環 id、開始時間、各任務的完成狀態／完成時間／所選科目（以任務 id 為鍵） |
| `history` | **已封存的歷史循環**：開始／結束時間＋當時整份清單的快照 |
| `meta` | **設定及資料版本**：schemaVersion、上次匯出時間等 |

- 預設清單只在 `meta` 不存在（第一次使用）時建立；刪光所有任務也不會被當成第一次使用。
- 每個操作都是一個「op」，同一個純函式同時用於畫面狀態與 IndexedDB 交易（讀取 → 套用 → 寫入在同一交易內），寫入依序排隊；連續快速點擊會合併成一筆交易，舊資料不會覆蓋新資料。寫入失敗會顯示錯誤並改回實際保存的內容。
- 開始新的一天：在同一個交易中檢查循環 id、封存快照、建立新循環；重複點擊只會成功一次。
- 歷史是複製出來的快照，之後的改名、刪除、排序都不會影響。

## 開發

```bash
npm install
npm run dev          # 開發伺服器
npm run typecheck    # TypeScript 檢查
npm test             # 單元測試（Vitest + fake-indexeddb）
npm run test:e2e     # 建置後以 iPhone 尺寸的 Chromium 跑端對端測試（Playwright）
npm run build        # 產生 dist/（含 sw.js）
npm run preview      # 以 /daily/ 子路徑模擬 GitHub Pages
```

技術：React + TypeScript + Vite，原生 IndexedDB，手寫 Service Worker（建置時自動產生預快取清單），無其他執行期相依套件。

## 部署

推送到 `main` 時，`.github/workflows/deploy.yml` 會測試、建置並部署到 GitHub Pages。第一次需要在 GitHub 啟用：

**Settings → Pages → Build and deployment → Source：選「GitHub Actions」。**

網站使用相對路徑與 hash 路由（`#/records`），所以在子路徑下重新整理不會 404。
